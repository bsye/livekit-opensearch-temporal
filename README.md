# LiveKit self-hosted (local, macOS)

The Linux production setup generated by LiveKit, run locally on macOS with
[OrbStack](https://orbstack.dev) (its `network_mode: host` behaves like Linux).

| Service | Address |
|---|---|
| LiveKit signaling (browsers) | `wss://livekit.localhost` |
| LiveKit signaling (backends, CLI, agents) | `ws://localhost:7880` |
| WHIP ingress | `https://whip.localhost/w` |
| RTMP ingress | `rtmp://livekit.localhost:1935/x` |
| Temporal UI | http://localhost:8233 |
| Temporal gRPC | `localhost:7233` (namespace `default`) |
| Webhook translator | `http://localhost:3100/webhook` |

Credentials are in `.env` (template: `.env.example`; must match `keys` in `infra/livekit/livekit.yaml`).

## Layout

```
docker-compose.yaml   all services; run docker compose from the repo root
infra/<service>/      config mounted into each container (livekit, ingress, egress, redis, caddy, temporal)
infra/linux/          original Linux production installer, for reference
data/                 runtime data written by containers (gitignored; data/caddy holds the local CA)
apps/livekit-temporal/ LiveKit webhook → Temporal translator + RoomSession workflow worker (TypeScript)
agents/               LiveKit agents (planned)
```

## Room sessions in Temporal

LiveKit posts webhooks (`webhook` in `infra/livekit/livekit.yaml`) to the translator in
`apps/livekit-temporal`, which verifies them and signal-with-starts one `roomSession`
workflow per room session:

- workflow id = room sid (`RM_…`); search attributes `RoomName`, `ParticipantIdentities`
- each webhook is a `livekitEvent` signal in the workflow history (duplicates are ignored by event id)
- `room_finished` completes the workflow after a 1-minute grace period for late webhooks;
  late events after that are dropped (reuse policy `REJECT_DUPLICATE`)
- query `roomState` for the live participants/tracks view

```sh
cd apps/livekit-temporal && npm install
npm run worker        # terminal 1
npm run translator    # terminal 2 (port 3100; 3000 is used by another project)
```

Filter in the UI with `RoomName="test"` or `ParticipantIdentities="me"`. From the CLI:

```sh
docker compose run --rm --no-deps --entrypoint temporal -e TEMPORAL_ADDRESS=temporal:7233 \
  temporal-namespace workflow query --workflow-id RM_xxx --name roomState
```

Temporal runs from `temporalio/server` with the vendored env-driven config in
`infra/temporal/config.yaml`; the one-shot `temporal-schema` and `temporal-namespace`
services (`infra/temporal/setup.sh`) create the Postgres schema, namespace and search
attributes on every `docker compose up`.

## Differences from the Linux setup

- `rtc.use_external_ip: false` in `infra/livekit/livekit.yaml` and `rtc_config.use_external_ip: false`
  in `infra/ingress/ingress.yaml`. With `true`, LiveKit advertises the public IP found via STUN,
  which isn't reachable from a laptop behind a router. Add `node_ip: <LAN IP>` if
  devices other than this Mac need to connect.
- Caddy can't install its local CA from inside the container, so it's trusted
  manually on the Mac (below).

## One-time setup

```sh
brew install livekit-cli

# start once so Caddy creates its CA, then trust it in the macOS keychain
docker compose up -d
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain \
  "$PWD/data/caddy/pki/authorities/local/root.crt"
```

Firefox: set `security.enterprise_roots.enabled=true` in `about:config`.
Node.js clients on `wss://`: `export NODE_EXTRA_CA_CERTS="$PWD/data/caddy/pki/authorities/local/root.crt"`.

## Run

```sh
docker compose up -d        # start
docker compose ps           # status
docker compose logs -f livekit
docker compose restart livekit ingress   # after editing infra/livekit or infra/ingress config
docker compose down         # stop

curl https://livekit.localhost           # should print OK
```

## CLI

Load the credentials into your shell (`lk` and the Agents SDK read these variables):

```sh
set -a; source .env; set +a
```

```sh
# join token for a browser client
lk token create --join --room test --identity me --valid-for 24h

lk room list
lk room participants list test

# join a bot that publishes demo video
lk room join --identity bot --publish-demo test
```

Test in a browser: https://meet.livekit.io → **Custom** → server `wss://livekit.localhost` + the token.

## Debugging media

- Browser: `chrome://webrtc-internals` — selected candidate pair, `outbound-rtp` /
  `inbound-rtp` stats and bitrate graphs.
- Server: `docker compose logs -f livekit | grep -E 'participant active|mediaTrack published|ice'` —
  `participant active` shows the selected ICE candidates and `connectionType`
  (`udp` is best; `tcp`/`turn` means a fallback).
